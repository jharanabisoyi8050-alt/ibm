Database Design

users

  • id, email, password_hash
  • role (ADMIN / OFFICER / PUBLIC)
  • name, phone, created_at
  • is_active, last_login

accident_reports

  • id, reported_by (FK users)
  • lat, lng (POINT/PostGIS)
  • severity (LOW/MED/HIGH/CRITICAL)
  • description, timestamp
  • is_confirmed (bool) — predicted vs real
  • source (USER / AI_PREDICTED)

traffic_records

  • id, location (POINT)
  • density_score (0–100)
  • avg_speed_kmh
  • congestion_level
  • vehicle_count, timestamp
  • is_simulated (bool)

road_conditions

  • id, location (POINT)
  • pothole_count, visibility
  • surface_quality (0–10)
  • weather_condition
  • risk_score, recorded_at

accident_hotspots

  • id, center_lat, center_lng
  • radius_m, risk_level
  • incident_count (last 90d)
  • last_updated

emergency_responses

  • id, accident_report_id (FK)
  • recommended_action (TEXT)
  • ai_recommendation (JSON)
  • human_approved (bool) — HITL
  • approved_by, response_time_s

ambulances

  • id, unit_code, status
  • current_lat, current_lng
  • hospital_base, crew_count
  • is_simulated (bool)
  • last_updated

agent_memory (vector)

  • id, agent_id, session_id
  • content (TEXT)
  • embedding (vector 1536)
  • metadata (JSONB)
  • created_at

token_usage_logs (cost monitoring)

  • id
  • agent_id
  • model_name
  • provider
  • prompt_tokens
  • completion_tokens
  • cost_usd
  • timestamp

AI Agent Communication Workflow

Orchestrator Agent

Routes user requests to specialist agents. Aggregates results. Manages HITL approvals. Uses IBM watsonx Granite.

LLM: watsonx Granite-3 | Memory: Redis + pgvector

Traffic Data Analysis Agent

Analyzes density, speed, congestion from live/simulated traffic feeds. Outputs structured traffic reports.

LLM: Gemini Flash | MCP: traffic_mcp, geo_mcp

Accident Risk Prediction Agent

Invokes XGBoost model. Considers weather + traffic + road conditions. Returns risk score 0–100 with explanation.

LLM: Claude Sonnet | MCP: weather_mcp | ML: XGBoost

Road Condition Monitoring Agent

Processes road surface data, pothole reports, visibility. Flags high-risk road segments.

LLM: Gemini Flash | MCP: geo_mcp, weather_mcp

Accident Hotspot Detection Agent

Runs DBSCAN clustering on historical accident data. Generates heatmap coordinates for the frontend.

LLM: watsonx Granite | ML: DBSCAN + scikit-learn

Emergency Response Agent

Analyzes accident reports and recommends response actions. Sends to HITL queue for human approval before dispatch.

LLM: Claude Sonnet | Guardrails: NeMo | HITL: yes

Ambulance Coordination Agent

Queries ambulance availability. Computes optimal routes using real-time traffic data. Clearly labels simulated vs real data.

LLM: Gemini Flash | MCP: ambulance_mcp, geo_mcp

Agent Communication Flow (per emergency event)

1
User / Sensor triggers accident report REST API receives report. Guardrails middleware validates input. JWT auth verified.
2
Orchestrator Agent receives task Routes to Traffic Agent, Risk Prediction Agent, and Road Condition Agent in parallel via LangGraph fan-out.
3
Specialist Agents execute via MCP tools Each agent calls its MCP tools (weather, geo, traffic). Results stored in agent memory (pgvector).
4
Hotspot Agent updates heatmap Re-clusters accident data. Pushes updated heatmap coordinates to frontend via WebSocket.
5
Emergency Response Agent generates recommendation Aggregates all agent outputs. Generates action plan with LLM. NeMo guardrails screen output.
6
Human-in-the-Loop review (HITL) High-severity recommendations sent to admin dashboard for human approval before dispatch notification.
7
Ambulance Coordination Agent dispatches Identifies nearest available (real/simulated) ambulance. Computes optimal route. Labels data source clearly.
8
Observability & cost logging All LLM calls traced via LangSmith. Tokens logged to token_usage_logs. Prometheus metrics updated.

Data Labeling Policy

All AI-predicted risk values carry source: "AI_PREDICTED". All confirmed accidents carry source: "CONFIRMED". All simulated ambulance/traffic records carry is_simulated: true with a visible badge in the UI. This distinction is enforced at the API and database level.

IBM Bob Agentic AI Integration Details

Custom Bob Mode

A workspace-scoped custom mode road-safety-ai in .bob/custom_modes.yaml with Agent + MCP + execute permissions and a road safety expert persona for all development tasks.

AGENTS.md Context

.bob/AGENTS.md documents the full system architecture, agent responsibilities, DB schema, and coding conventions so IBM Bob has precise project context on every task.

MCP Tool Server

Custom Python MCP server exposing 4 tool groups: traffic_tools, weather_tools, geo_tools, ambulance_tools. Registered in Bob's MCP config for live agent use.

Model Gateway

IBM Bob Enterprise Model Gateway routes to 3 providers (watsonx, Bedrock, Vertex). Token usage and costs logged per agent. Static router ensures each agent uses its optimized model.

Guardrails

NeMo Guardrails screens all agent inputs/outputs. Provider-level guardrails (Bedrock guardrailConfig) for frontier models. Custom safety rules for emergency dispatch actions.

Observability

LangSmith captures every agent trace. Prometheus collects response latency and error rates. Grafana dashboards for traffic authorities. LangSmith datasets power automated evaluation.
